Foundations / Color

Color

Color in Concord is organized as a hierarchy of decisions rather than a collection of isolated hex values. Foundation palettes provide raw visual vocabulary, system tokens create the theme boundary, semantic tokens describe purpose, and components consume those roles without encoding a palette into their own implementation.

Visual foundation

From palette to purpose

Concord separates available color from interface meaning. The foundation remains a reusable vocabulary while system and semantic roles create the contracts that themes and components actually depend on.

Palette is vocabulary, not a contract

Foundation palettes answer a low-level question: which colors are available to the system? They provide reusable source material, but they do not define interface meaning. A component should not need to know that a primary action currently resolves to a particular blue, green, plum, or neutral value.

Keeping raw palette values separate from interface roles allows the visual language to evolve without forcing component structure or semantics to change with it.

Roles create a stable interface

System color tokens promote palette values into stable contracts for brand, content, surfaces, borders, and feedback. This is the theme boundary: a theme can redefine the visual character of Concord while preserving the roles used downstream.

Semantic tokens then describe why a color is used rather than what it looks like. Primary action, raised surface, strong text, focus border, selection, and critical feedback remain recognizable interface intentions even when their resolved colors change. Components consume those roles instead of reaching backward into a raw palette.

Color and accessibility

Color should reinforce meaning rather than carry it alone. Status, selection, focus, validation, and interactive state must remain understandable through text, structure, iconography, native state, or other visible cues.

Theme flexibility also creates a responsibility to validate foreground and background relationships whenever a theme changes a filled surface, border, focus treatment, or feedback color. The token architecture makes those relationships controllable; accessibility determines whether the resulting combinations remain usable.
