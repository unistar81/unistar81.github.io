Foundations / Sizing

Sizing

Sizing in Concord is contextual rather than universal. Shared typography and spacing provide reusable foundations, while dimensions that belong to a control, marker, track, or component variant remain owned by the contract that gives that dimension meaning.

Dimensions belong to context

Concord does not force unrelated dimensions into a universal size scale. The examples below come from real component contracts and are intentionally different.

Dimensions belong where decisions belong

A checkbox control, slider thumb, toggle track, progress marker, and button do not become the same design decision simply because each has a measurable width or height. Artificially coupling them through one universal size scale would make unrelated components change together.

Concord keeps dimensions close to the context that owns them, while still allowing those contracts to reference shared typography, spacing, radius, or other Foundation values where a genuine relationship exists.

A size variant is an intentional component choice

When a component exposes small, medium, or large variants, the variant changes approved dimensions while preserving the same semantic and interaction contract. Button is a current example: its size variants change tokenized padding and typography rather than introducing separate component implementations.

Size remains independent from content width. A longer label can still require more inline space even when the component stays on the same size variant.

Density is a separate system axis

Component size and system density solve different problems. A component size is selected for that component; density changes the spatial character of many components at once.

Keeping those axes separate allows a medium control to remain medium in compact, default, or spacious density while approved downstream dimensions adapt. Interactive targets, text zoom, long labels, and intrinsic sizing still need to remain usable throughout those combinations.
