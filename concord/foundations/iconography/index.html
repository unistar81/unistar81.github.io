Foundations / Iconography

Iconography

Icons in Concord are a lightweight visual layer that supports the meaning already established by semantic HTML, text, and component state. The icon source is shared, scalable, and color-agnostic: individual symbols inherit their visual context instead of carrying separate hard-coded color variants.

Symbols support semantics

An icon can make an action or state easier to scan, but the symbol is not the accessible name. Decorative icons can remain hidden from assistive technology when adjacent text already carries the meaning; icon-only controls need an explicit accessible name; status icons should reinforce meaningful status text rather than replace it.

Keeping those responsibilities separate allows the same visual symbol to appear in a button, alert, field, or navigation context without changing the semantic contract of the surrounding interface.

Context owns appearance

Concord icons use `currentColor`, so the surrounding component or semantic role determines their color. A search icon can inherit normal content color, a status icon can follow feedback color, and an icon inside a themed action can follow that action's foreground without maintaining another set of colored SVG assets.

This also makes the icon layer naturally theme-aware. The symbol itself remains stable while the system around it changes visual expression.

Scale without changing the asset

Icons are masked vector graphics and can be resized through the shared icon size contract without introducing separate raster assets. Size should follow the context: compact controls need a different optical relationship than larger actions or standalone status marks.

Scaling still has to preserve alignment, readable surrounding text, sufficient target size for interactive controls, and resilience when text zoom or content wrapping changes the composition.
