Foundations / Typography

Typography

Typography in Concord is a shared system contract rather than a collection of local font declarations. Foundation values define the available families, sizes, weights, and line heights; system roles turn selected values into a stable hierarchy that components can consume and themes can intentionally redefine.

Type is a system decision

Typography affects hierarchy, rhythm, density, and the amount of content an interface can hold. Those decisions become difficult to evolve when individual components choose their own font sizes, weights, or family stacks.

Concord keeps the raw vocabulary in foundation tokens and promotes selected values into system roles. Components can therefore consume a named body or heading contract without owning the numerical value behind it.

Scale becomes hierarchy

A type scale provides possibilities; roles establish meaning. Concord's system typography maps selected foundation sizes to small text, body text, body large, and three heading levels. The same separation applies to regular, medium, semibold, and bold weight contracts.

Because the role remains stable, an expressive theme can change the resolved size of a heading or body role without requiring components to invent a second typographic implementation.

Readability must remain resilient

Typography has to survive more than the preferred font and ideal amount of content. Fallback families, long labels, text zoom, constrained widths, and larger themed type can all change line length and wrapping.

Line height should preserve readable rhythm as size changes, and components should remain usable when text occupies more space than the default specimen suggests. A typographic system is successful when hierarchy remains clear without making layout correctness depend on one exact font rendering.
