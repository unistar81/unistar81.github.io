LAYOUT

Flow

Flow creates consistent block-axis spacing between adjacent direct children while leaving layout in normal document flow. Use it when one container should own a vertical sibling relationship without introducing Flexbox or Grid.

Layout contract

Normal flow owns the stack. Flow owns sibling spacing.

Direct children keep normal document flow, intrinsic sizing, and source order. Flow owns only the block-axis space between adjacent siblings.

SIBLING SPACING CONTRACT

One container. Three direct children.

Each child keeps its own content and intrinsic size. The parent owns only the space between their outer boundaries.

Normal flow remains in control

Flow does not create a new formatting model. Direct children remain in normal document flow and keep their intrinsic sizing, semantic order, and native block behavior. .dsl-flow only governs the spacing relationship among those siblings.

HTML 
<section class="dsl-flow" aria-labelledby="account-settings-title">
  <header>
    <h2 id="account-settings-title">Account settings</h2>
    <p>Update the information used across your profile.</p>
  </header>

  <label>
    Display name
    <input name="display-name" />
  </label>

  <div>
    <button type="submit">Save changes</button>
  </div>
</section>

Space exists only between direct siblings

Flow normalizes direct-child block margins and applies its shared space only when one direct child follows another. The first child receives no leading Flow space, and the last child receives no trailing Flow space from the primitive.

This keeps spacing ownership on the parent instead of asking every child to manufacture matching outer margins.

Public configuration

Sibling space --dsl-flow-space
Space inserted between adjacent direct children. Default · semantic layout content gap · 16px fallback

Apply the property to the Flow container or its owning composition. Internal --_dsl-* properties are implementation details, not public API.

Use Flow when one container owns the stack

Use Flow for form sections, article subsections, settings groups, compact content stacks, and other block-axis sequences where one parent should govern the space between its direct children.

The children do not need to share the same internal structure. A heading block, field, component, or action region can participate as long as the parent owns their sibling spacing relationship.

Flow stops at the direct-child boundary

Flow manages spacing among direct sibling components or content blocks. It does not reach into their descendants or replace component-owned internal spacing.

If a child needs its own internal arrangement, that child owns the appropriate layout mechanism for that relationship.

Preserve meaning and source order

Flow changes spacing, not document meaning or order. Keep semantic source order meaningful for reading, keyboard navigation, and assistive technology; do not use spacing to imply a hierarchy that the document structure does not express.
