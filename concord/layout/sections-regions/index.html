Sections & Regions

Sections & Regions separates two decisions that are often accidentally combined: what a major page area means and how much block-axis breathing room its content needs. Semantic HTML owns meaning. .dsl-region adds spacing geometry without choosing a background, border, theme, or component.

Layout contract

Section meaning, region spacing, and surface ownership stay separate

Semantic HTML describes the page area. Region spacing adds block-axis breathing room inside that area, while product and theme styling can change without changing the Layout contract.

One spacing contract .dsl-region adds space inside the region boundary

Meaning comes from semantic HTML

Choose the host element for its meaning, not for the Layout class. Use <section> for a meaningful thematic grouping, <aside> for supporting or tangential content, and a div when no more specific semantic element applies.

Applying .dsl-region changes geometry only. It does not create a section, landmark, or ARIA region role. When a native section should be exposed as a named region, give it an appropriate visible heading and accessible name through the semantic HTML.

HTML 
<section
  class="dsl-region feature-surface"
  aria-labelledby="feature-title">
  <div class="dsl-container">
    <h2 id="feature-title">Featured stories</h2>
    ...
  </div>
</section>

Region spacing is inside the region

.dsl-region sets block-axis padding, so the space sits inside the region box between its boundary and its content. If the same host owns a background or surface class, that surface extends through the padding. Adjacent surfaces can meet at the region boundary while their content keeps consistent vertical breathing room.

Use .dsl-container inside when the content also needs a bounded inline width. The two rules stay independent: .dsl-region controls block-axis spacing; Content Boundary controls usable inline width.

Public configuration

Major region spacing

--dsl-region-space

Sets the block-start and block-end padding applied by .dsl-region. The current default falls back to --dsl-foundation-space-500 at 48px. Override it only when the page composition has a legitimate structural reason to change the normal major-region spacing.

Spacing ownership

Each layer should own only the space created by its relationship.

Keeping those responsibilities separate prevents page spacing from leaking into components or surface styles.

  • Component internals use component-owned spacing.
  • Local content composition uses the gap or spacing rule owned by that composition.
  • Major page regions use .dsl-region when they need consistent block-axis breathing room.
  • Content Boundary owns inline width and page-edge gutters, not vertical section spacing.

Nesting

Semantic sections may nest because the content hierarchy requires them. Do not add another .dsl-region merely because a nested <section> exists.

Add .dsl-region to the nested area only when it genuinely begins a new major page-region spacing boundary. Otherwise let the surrounding composition own the local spacing and avoid accidental double padding.
