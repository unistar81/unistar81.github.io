Responsive Composition

Responsive composition chooses how a relationship adapts when its conditions change. Start with CSS that can absorb change continuously; introduce a discrete condition only when the condition has a clear owner.

Layout contract

Match the mechanism to the condition that changed

Start with continuous CSS. If a discrete state change is necessary, identify the condition owner and choose the matching mechanism: local space, content structure, or viewport / environment.

01 · CONTINUOUS ADAPTATION Can CSS preserve the relationship without a threshold?

Start with the mechanisms that naturally absorb changing space and content.

normal flow wrapping minmax() auto-fit
OUTCOME No query Stay continuous while the relationship still works.
02 · DISCRETE STATE CHANGE If a different state is genuinely needed, identify what changed.
LOCAL SPACE Containing width changed @container

The reusable composition owns the threshold because it knows when its local relationship stops working.

CONTENT STRUCTURE Presence or hierarchy changed Pattern-owned condition

The Pattern owns content-aware composition. Use :has() when CSS can express the structural condition.

VIEWPORT / ENVIRONMENT Macro condition changed @media

The page shell or environment owns the response when the condition is truly global.

RULE OF OWNERSHIP Respond to the condition that changed, not a device category.

Continuous adaptation comes first

Normal flow, wrapping, intrinsic sizing, `minmax()`, and `auto-fit` can often absorb changing space or content without a threshold. That is responsive behavior, not a fallback. Keep the relationship continuous until it genuinely needs a different state.

Identify the owner of the change

When continuous CSS no longer preserves the relationship, identify what changed before choosing a mechanism. Local space belongs to the composition; content presence or hierarchy belongs to a higher-level Pattern; viewport or environment conditions belong to the page shell or environment. This is not an escalation ladder, and device names are not conditions.

Local space belongs to the composition

Available Width establishes how local space can be queried. The composition owns what changes when that local space no longer supports the relationship. Keep the threshold with the composition that understands the content.

The 24rem threshold is the same composition-owned example used on Available Width. It is not a Concord breakpoint token, phone size, or tablet size.

CSS 
.account-summary {
  display: grid;
  grid-template-columns: minmax(0, 1fr) auto;
}

@container (max-width: 24rem) {
  .account-summary {
    grid-template-columns: 1fr;
  }
}

Content structure is a different condition

Width is not the only input that can change a composition. A known child, supporting region, or content hierarchy may make a different arrangement more appropriate even when width is unchanged. Keep content-specific behavior in the Pattern that owns that content contract; do not make the base Grid infer product structure.

Use `:has()` when the structural condition is expressible in CSS and belongs to the Pattern. Do not use a width query as a proxy for content that may or may not exist.

Viewport and environment stay macro

Media queries remain appropriate when the condition belongs to the viewport or environment. Use a media query when the page shell itself must change or an environment-owned condition genuinely changed. Reusable local compositions should not inherit global device categories merely because the viewport is available.

Reflow must preserve meaning and operability

Responsive composition must remain usable under zoom, enlarged text, long translations, narrow containers, and changed writing direction. Preserve meaningful DOM and focus order, accessible names, and essential actions. Let content wrap. Avoid fixed dimensions that clip content, and avoid visual reordering that makes reading order diverge from DOM or focus order.
