LAYOUT

Split

Split keeps two direct sibling groups at opposite inline edges while local space allows. When their combined intrinsic size no longer fits, the same siblings wrap onto additional rows without changing source order or requiring a viewport breakpoint.

Layout contract

Split keeps two sibling groups apart while space allows

Split owns one two-sibling relationship: keep the groups at opposite inline edges while they fit, then allow those same siblings to wrap when their combined intrinsic size exceeds local available width.

Flexbox owns the two-sibling relationship

Use Split when one parent owns exactly two peer groups that should separate across the available inline space. .dsl-split uses wrapping Flexbox with justify-content: space-between so the parent owns both the separation and the fallback behavior.

The children keep their own meaning and internal layout. Split owns only the relationship between those two direct children.

HTML 
<div class="dsl-split">
  <div>
    <span>Workspace</span>
    <strong>Quarterly planning</strong>
  </div>
  <button type="button">Create project</button>
</div>

Wrapping follows the combined intrinsic size

A Split should not switch because a phone, tablet, or desktop threshold was crossed. It wraps when the two sibling groups, their gap, and the local space they receive can no longer coexist comfortably on one row.

The same source order remains before and after wrapping. The second sibling simply moves onto another flex line when the relationship no longer fits.

Gap and alignment belong to the Split container

Use --dsl-split-gap for separation between the two direct children and between wrapped rows. Use --dsl-split-align for cross-axis alignment while both siblings share a flex line.

Keep these decisions on the parent that owns the relationship instead of manufacturing matching margins or alignment rules inside the children.

Public configuration

Split exposes two relationship-level custom properties. Set them on the Split that owns the two-sibling relationship; separation and wrapping remain intrinsic.

Gap --dsl-split-gap
Space between the sibling groups and between wrapped rows. Default · semantic layout content gap · 16px fallback
Cross-axis alignment --dsl-split-align
Alignment of the two sibling groups while they share one flex line. Default · center

Inline distribution is intentionally fixed at space-between. Split is a specific relationship, not a general Flexbox utility API.

Use Split for compact two-part relationships

Good uses include title + action, label + value, summary + control, metadata + action, or two compact peer groups where the second group should stay away from the first while room exists.

The key requirement is the two-sibling relationship, not a particular component type or visual treatment.

Choose another primitive when the relationship differs

Use Cluster when several peer items participate in one wrapping sequence. Use Flow for a vertical sibling stack. Use Grid when rows and columns share meaningful track relationships. Use Sidebar when one substantial content region and a supporting region need an asymmetric main/support relationship.

Split is intentionally narrower than those primitives.

Split is not page structure

Do not use Split to build application shells, page columns, or substantial multi-region compositions. A page-level main/support relationship belongs to Sidebar or Grid because those layouts carry different sizing and ownership semantics.

Split should remain a small composition relationship between two peer groups.

Preserve source order and content resilience

Wrapping changes geometry, not document meaning. Author the two sibling groups in the order that remains sensible when they stack, and keep keyboard and assistive-technology traversal aligned with that source order.

The relationship must tolerate content growth, localization, zoom, and narrow available space. Do not force fixed child dimensions merely to preserve the side-by-side state.
