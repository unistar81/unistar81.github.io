LAYOUT

Layout Overview

Layout is Concord's spatial system for page structure. Native HTML gives sections and landmarks their meaning; CSS classes control content width, spacing between major page sections, content arrangement, and how layouts adapt as available space changes.

Layout contract

A spatial system built from relationships

Choose by relationship

Use the smallest layout mechanism that owns the behavior

Choose from the relationship between children—not from a page name, framework, or device category.

  • 01 · Flow Stacked direct siblings One parent owns block-axis spacing.
  • 02 · Cluster Wrapping peers Inline peers wrap while sharing one gap and alignment rule.
  • 03 · Split Separated peer groups Two peer regions occupy opposite sides when space allows.
  • 04 · Sidebar Main + supporting region Unequal regions stay beside each other until local width runs out.
  • 05 · Grid Tracks and placement Use explicit rows, columns, spans, or repeated two-dimensional structure.

Design decisions at a glance

The Layout model gives Product Design and Engineering a shared four-step contract. Product Design defines the intended spatial relationship; Engineering implements it with the smallest Concord layout mechanism that preserves that intent.

  • Structure — What meaningful sections and landmarks make up the page?
  • Content boundary — How wide should the content be, and where should it sit within the available space?
  • Composition — How should content within that boundary be arranged and related?
  • Adaptation — What should change when that composition gains or loses available space?

What Layout owns

Layout owns the spatial relationships that organize page content. It does not determine component internals, content ranking, editorial prominence, or complete page templates; those responsibilities stay with Components, Patterns, and Templates.

  • page content boundaries and readable content widths;
  • spacing around major page sections;
  • grids, tracks, gutters, and content placement;
  • responsive behavior based on available space;
  • reusable layout relationships such as Flow, Cluster, Split, and Sidebar.

Public CSS contract

CSS classes, not custom elements. Use these classes on the native HTML elements that already communicate the page's meaning. Concord adds layout behavior; it does not replace semantics.

Here, `<section>` identifies a semantic page section, `.dsl-region` adds the spacing around that major section, and `.dsl-container` constrains and centers its content.

Flow, Cluster, Split, and Sidebar are small reusable relationships rather than page types: Flow spaces stacked content, Cluster wraps related inline items, Split separates two content groups, and Sidebar creates a main-content + sidebar arrangement. Their dedicated pages show when each relationship is appropriate.

CSS 
.dsl-container       /* constrains and centers page content */
.dsl-region          /* adds spacing around major page sections */
.dsl-grid            /* creates a responsive grid for repeated content */
.dsl-layout-context  /* establishes a container for local responsive rules */
.dsl-flow            /* adds consistent spacing between stacked content */
.dsl-cluster         /* groups related items inline and wraps them when needed */
.dsl-split           /* places two content groups on opposite sides */
.dsl-sidebar         /* creates a main-content + sidebar layout */
HTML 
<section class="dsl-region">
  <div class="dsl-container">...</div>
</section>

Composition ladder

Layout controls spatial relationships. Patterns combine those relationships around a content need. Templates assemble Patterns into recognizable pages. Keeping those responsibilities separate prevents page-specific rules from leaking into reusable components.

For example, a Sidebar relationship can provide the spatial arrangement for a search-and-filtering Pattern; a List / Index Page Template can then combine that Pattern with results, pagination, and other page-level needs. Layout defines the relationship, the Pattern gives it product meaning, and the Template places it in a recognizable page.

Architecture lineage

Concord evolves spatial relationships proven in an earlier multi-brand enterprise architecture: stable content boundaries, consistent spacing between page sections, responsive collections, and content-aware composition across many brands and migrations. The current implementation preserves those relationships while expressing them with modern platform capabilities such as intrinsic sizing, CSS Grid, container queries, logical properties, `subgrid`, and structural selectors where the content strategy genuinely requires them.
