Placement & Spans

Placement and spanning are deliberate tools for hierarchy, asymmetry, and shared alignment. Concord keeps Grid coordinates with the Pattern or Template that defines the relationship instead of exposing device-specific span and offset classes.

Layout contract

Placement belongs to the composition that defines the grid

Line positions and spans express roles inside an explicit Grid. Keep those coordinates with the Pattern or Template that defines the relationship instead of turning them into global span and offset utilities.

Explicit placement needs a defined grid

Placement starts with an explicit grid when role-specific coordinates are actually necessary. Repeating peers should stay in normal Grid auto-placement whenever track sizing and document order already express the relationship.

When explicit placement is warranted, keep the track template and the role placement together so the coordinate system is understandable where it is authored.

1 / 5 starts at Grid line 1 and ends at line 5, so the feature spans four tracks. 5 / 7 spans two tracks. 2 / 6 spans four tracks while intentionally leaving the outer tracks available for asymmetry.

The parent composition owns both the explicit template and these role relationships. Children do not carry generic span or offset utility classes.

CSS 
.feature-layout {
  display: grid;
  grid-template-columns: repeat(6, minmax(0, 1fr));
}

.feature-layout > .feature {
  grid-column: 1 / 5;
}

.feature-layout > .support {
  grid-column: 5 / 7;
}

.feature-layout > .secondary {
  grid-column: 2 / 6;
}

Choose coordinates or spans by intent

Use start and end lines such as grid-column: 1 / 5 when both location and extent are part of the composition. Use a span such as grid-column: span 4 when the extent matters but auto-placement may choose the start.

Named lines or named areas can improve readability when a durable composition has stable roles. Choose the representation that communicates the relationship most clearly rather than the shortest syntax.

Asymmetry does not require offset utilities

Intentional empty tracks can create asymmetry without an abstract offset API. For example, grid-column: 2 / 6 leaves one track before and one after the secondary region because that placement belongs to this composition.

Concord does not need .span-4, .offset-2, or viewport-prefixed placement classes by default. If repeated product use eventually proves a stable shared relationship, promote that relationship as a named Pattern or composition contract rather than a presentation-class matrix.

Responsive placement belongs to the composition

Explicit placement is not permission to freeze a desktop arrangement. When the relationship no longer works at the local space the composition receives, the owning composition should release or redefine its coordinates using the responsive mechanism that owns that change.

A container-aware composition may collapse several explicitly placed regions back to the full Grid when its local space crosses a meaningful threshold. That threshold belongs to the composition, not to a phone, tablet, or desktop label.

Preserve source order and content resilience

Grid coordinates change visual geometry; they do not change DOM or focus order. Author meaningful source order first and avoid placement that makes the visual reading sequence contradict keyboard or assistive-technology traversal.

A placed region still owns its internal wrapping, minimum sizing, and content resilience. Do not force descendants into fixed dimensions merely to preserve one arrangement.
