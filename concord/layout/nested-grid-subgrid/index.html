Nested Grid & Subgrid

Nested layout has two different ownership models. A child can establish its own local Grid, or it can share parent tracks when alignment across that parent-child boundary is part of the composition. Concord chooses between those relationships deliberately rather than treating every nested Grid as a candidate for subgrid.

Layout contract

Nested Grid creates local tracks. Subgrid shares parent tracks.

A nested Grid creates a new coordinate system. Subgrid keeps the child on the parent's track system when alignment must continue across that boundary.

Rule of ownership Stay independent by default. Use subgrid only when shared parent alignment is the requirement.

Nested Grid creates a new coordinate system

Use a normal nested Grid when the child composition owns its internal geometry. Its tracks are local to that child and do not need to line up with the parent's track boundaries.

This is the default relationship when independence is useful. The parent decides where the child sits; the child decides how its own content is arranged.

CSS 
.card-collection {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
}

Subgrid continues the parent coordinate system

Use `subgrid` when descendants genuinely need to align with tracks established by the parent Grid. The child still remains a Grid container, but the subgridded axis uses the parent's track sizing rather than defining a new set of tracks.

Here each `.detail-row` spans the parent columns and its descendants participate in those same column tracks. The alignment relationship is explicit instead of being recreated with a copied template.

CSS 
.detail-list {
  display: grid;
  grid-template-columns: 12rem minmax(0, 1fr) auto;
}

.detail-row {
  display: grid;
  grid-template-columns: subgrid;
  grid-column: 1 / -1;
}

Share only the axis that needs alignment

Subgrid is axis-specific. A composition may share parent columns while allowing its rows to remain local, or share rows while defining independent columns.

Use `grid-template-columns: subgrid` when column alignment crosses the parent-child boundary. Use `grid-template-rows: subgrid` when the shared relationship is on the block axis. Use both only when both axes genuinely belong to the parent track system.

Do not copy parent track definitions

Repeating the parent's `grid-template-columns` inside a child can make two grids look aligned at one moment, but it does not create a shared track relationship. The definitions can drift as content, sizing, or the parent composition changes.

If shared alignment is the requirement, express that relationship with subgrid. If independence is the requirement, keep the nested Grid self-contained.

Subgrid is local, not a page-wide master grid

Do not use subgrid to turn the page into one global coordinate system that every descendant must inherit. Shared tracks should follow a meaningful parent-child composition relationship.

A Pattern or Template may expose a stable parent Grid when its descendants need coordinated alignment. Unrelated components should continue to own their own internal layout.

Preserve meaning and content resilience

Nested Grid and subgrid change geometry, not document meaning. Keep source order, semantics, accessible names, and focus order meaningful without relying on visual track placement.

Shared alignment must also tolerate content growth, localization, zoom, and narrow available space. Do not use inherited tracks as a reason to force descendants into fixed dimensions.
