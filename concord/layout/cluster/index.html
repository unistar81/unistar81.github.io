LAYOUT

Cluster

Cluster arranges related peer items in one wrapping inline relationship. The items keep their source order and intrinsic size; the Cluster owns the gap, cross-axis alignment, and inline distribution while local available width determines when whole items move to another row.

Layout contract

Cluster keeps related peers in one wrapping relationship

Cluster owns the gap, alignment, justification, and wrapping relationship between direct children. Children keep their own meaning, intrinsic size, and appearance.

SIBLING WRAPPING CONTRACT

Same peers. Different available width.

Only the containing space changes. Item order, gap, alignment, and content stay the same.

Flexbox owns the one-dimensional relationship

Use Cluster when direct children participate in one inline sequence. .dsl-cluster uses Flexbox because the relationship is one-dimensional even when wrapping creates additional visual rows.

The children remain ordinary semantic content. Cluster changes their spatial relationship; it does not assign meaning or require a particular component type.

HTML 
<div class="dsl-cluster">
  <span>Design systems</span>
  <span>Accessibility</span>

</div>

Wrapping follows available space

No breakpoint is required. As available inline space decreases, flex-wrap: wrap moves whole items onto additional rows while preserving source order and the configured gap.

The relationship remains the same before and after wrapping. Only the amount of local space available to the Cluster changed.

Gap belongs to the Cluster container

Spacing between peers belongs to the parent relationship. Use --dsl-cluster-gap on the Cluster rather than manufacturing matching outer margins on every child.

The children still own their internal spacing. Cluster owns only the separation between its direct children.

Alignment and distribution are container decisions

--dsl-cluster-align controls cross-axis alignment within each flex line. --dsl-cluster-justify controls inline distribution of the items within the available row.

Keep these values on the Cluster that owns the relationship. Do not encode alignment or distribution into otherwise reusable child components.

Public configuration

Cluster exposes three relationship-level custom properties. Set them on the Cluster that owns the peer relationship; wrapping itself remains intrinsic.

Gap --dsl-cluster-gap
Space between adjacent direct children, including between wrapped rows. Default · semantic layout content gap · 16px fallback
Cross-axis alignment --dsl-cluster-align
Alignment of peers within each flex line. Default · center
Inline distribution --dsl-cluster-justify
Distribution of peers across the available inline space. Default · flex-start

These properties tune one Cluster relationship. They are not component-internal tokens and do not create viewport-specific modes.

Use Cluster when peers share one inline relationship

Good uses include compact action groups, metadata, filters, badges or tags, small navigation groups, and related controls that should remain peers while wrapping naturally.

The key requirement is not the visual treatment of the children. The requirement is that the children participate in one inline relationship with shared gap and alignment rules.

Choose another primitive when the relationship differs

Normal text already wraps through the inline formatting model and does not need Cluster. Use Flow for a vertical sibling sequence, Split when two peer regions should occupy opposing inline edges, and Grid when rows and columns form meaningful shared track relationships.

Do not use Cluster merely because several items happen to appear next to each other in one screenshot.

Preserve source order and meaning

Wrapping changes geometry, not document meaning. Keep source and focus order meaningful so moving an item onto another visual row does not create a contradictory reading or keyboard sequence.

Cluster should tolerate content growth, localization, zoom, and narrow available space without requiring fixed child dimensions.
