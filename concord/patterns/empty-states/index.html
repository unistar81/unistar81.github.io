Patterns / Content & Collections

Empty States

An empty state explains a known absence of expected content, preserves the surrounding context, and offers the next useful step when one exists. It should describe why the collection is empty rather than decorating the absence.

Composition boundary

Empty States owns the explanation and recovery composition for a known-empty scope; it does not own the underlying collection, search logic, permissions, loading state, or product action. The collection component or page region still owns its normal structure. Search & Filtering owns the criteria that may have produced zero matches. Loading & Progress owns work whose result is not known yet. Status Messaging owns transient workflow outcomes that do not replace the collection.

The consuming application owns whether content exists, why it is unavailable, whether an action can create or restore content, authorization, data fetching, persistence, and any action triggered from the state. Concord does not introduce a dedicated Empty State component or product-specific empty-state API.

Identify the actual state

  • Unknown is not empty. If loading, refresh, or an unresolved request means the application does not yet know whether content exists, use Loading & Progress rather than an Empty State.
  • Failure is not zero. A request error is a recovery state and must not masquerade as "No results."
  • Unavailable or restricted is not an empty collection. If content may exist but cannot currently be shown, explain the known reason instead of presenting the condition as zero items.
  • Completed or cleared may need no recovery action. A valid zero state such as a finished queue or cleared workflow can simply confirm the outcome when there is nothing useful to do next.

Choose the state from what the application knows

The visual treatment may remain related across these conditions, but the message and recovery model must follow the state meaning. Do not make every absence look like the same "nothing here" template.

  • No content has been created yet - Empty State: first use. Explain what belongs here and offer creation or setup when it is genuinely useful.
  • Content exists, but the active criteria return zero matches - Empty State: no matches. Preserve the criteria and offer a proportional way to broaden or clear them.
  • The workflow intentionally reduced the collection to zero - Empty State: completed / cleared. Confirm the valid outcome; an action may be unnecessary.
  • Data is still being fetched or refreshed - Loading & Progress, not Empty State. The application does not yet know that the collection is empty.
  • The request failed - Error / recovery state, not Empty State. Preserve the context required to retry.
  • Content may exist but cannot currently be shown - Empty State: unavailable / restricted. Explain the known reason and recovery path when one exists.

Content & recovery

  • Name the absent content or outcome. Prefer "No documents match these filters" over generic copy such as "Nothing here."
  • Explain the cause users can act on. Supporting text should add the minimum context needed to understand why the state occurred and what can change it.
  • Offer an action only when it is meaningful. First-use states may warrant a clear primary creation action; no-match states may offer reset or adjustment. A valid completed state may need no action at all.
  • Keep recovery proportional. Prefer one obvious recovery path. Add secondary actions only when they represent genuinely distinct useful choices rather than filling visual space.
  • Preserve user work. A no-match state should not silently clear search terms, filters, sort state, or other context merely to make results reappear.
  • Avoid decorative dominance. A restrained icon or illustration may reinforce meaning, but it must not become the primary content, push recovery below the fold, or imply meaning unavailable in text.

Placement & collection relationship

  • Place the Empty State where the missing content would normally appear. Keep page title, navigation, search/filter controls, and other still-useful context available.
  • Scope the message to the affected region. A local empty collection should not replace the entire page when surrounding content and actions remain useful.
  • Keep collection navigation consistent. Pagination or result-range controls should normally disappear when the current result set contains no pages, while the query/filter state remains available.
  • Do not render fake empty rows or cards. Replace the absent collection content with one understandable state rather than repeating placeholder rows that look selectable.
  • Return to the normal collection contract when content appears. Empty-state markup should not force a different page architecture once the collection is populated.

Search & filtering recovery

  • Keep the criteria visible. Users should be able to understand which query or filters produced zero matches without reopening hidden state unnecessarily.
  • Reset only the criteria the recovery action names. "Clear filters" should not also erase the search query unless the product explicitly labels and intends that broader reset.
  • Do not move focus merely because results become empty. Keep focus on the search/filter control the user is operating; announce a meaningful result-count change through the owning Search & Filtering status relationship when needed.
  • Let the Empty State explain; let Search & Filtering execute. The Pattern may contain a recovery Button, but query mutation, URL updates, refetching, and restored results remain application behavior.

Accessibility & responsive behavior

  • Use ordinary structural semantics. A heading and supporting paragraph usually provide enough structure. Do not add `role="alert"`, `role="status"`, or a live region merely because content is absent.
  • Avoid duplicate announcements. When an asynchronous search already announces "0 results," do not make the entire Empty State another competing live region.
  • Keep actions in normal keyboard order. Do not automatically move focus into an Empty State unless a workflow explicitly requires a recovery destination.
  • Keep text to a useful readable measure. Empty states should remain understandable without becoming a wall of centered copy across a wide container.
  • Allow localization and narrow layouts. Titles, explanations, and actions must wrap without clipping, horizontal scrolling, or dependence on an illustration's geometry.
