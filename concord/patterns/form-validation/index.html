Form Validation

Form validation coordinates constraints, feedback, and recovery when entered information cannot yet be accepted. It identifies what needs attention without discarding useful input or turning every validation event into an interruption.

A failed submission preserves the entered value, identifies the affected field, and explains the correction without replacing the Input contract.

Composition boundary

Form Validation owns feedback and recovery, not the validation rule itself. Native HTML and canonical field components expose constraints and invalid state. Product or domain logic owns requirements Concord cannot know. This pattern owns when feedback is presented, how it is associated with the affected field or group, and how the user can recover. Form Field owns the local label, control, supporting-description, and message geometry so validation does not need a second spacing system.

Use native constraints such as `type`, `required`, `min`, `max`, `minlength`, and `maxlength` when they accurately express the requirement. Add `pattern` only when the consuming product has a genuine narrower rule; Concord should not encode locale- or domain-specific validation rules into a general-purpose field contract.

Validation sequence

  • Define the constraint. Prefer native HTML constraints where they accurately express the requirement; keep business and server rules in the consuming application.
  • Choose the validation moment. Do not mark untouched fields invalid while users are still entering information. A failed attempt to continue or submit is a safe default; some fields may validate after meaningful interaction.
  • Preserve the value. Do not erase or silently rewrite the user’s input simply because validation failed.
  • Identify the problem. Apply the canonical invalid state and expose `aria-invalid="true"` when the entered value is known to be invalid.
  • Explain the correction. Keep a specific human-readable message adjacent to the affected control or group and associate it programmatically.
  • Recover cleanly. When the value becomes valid, remove the obsolete invalid state and error message without disrupting focus or reading order.

Message guidance

  • Describe the correction, not merely the failure. Prefer “Enter a complete email address, such as name@example.com.” over “Invalid email.”
  • Keep messages specific. Explain what the user can change next; avoid blame-oriented copy.
  • Keep field errors local. A field-specific message belongs with the field it explains.
  • Return server errors to the same recovery model. If a server-side rule belongs to one field, such as an address already associated with an account, expose it through the same field-error relationship.
  • Do not duplicate the rule in placeholder text. Essential validation guidance must remain available after the user begins typing.

Accessibility & recovery

  • Associate the message. Connect field-level error text with the affected control using the canonical descriptive relationship.
  • Validate groups as groups. When a requirement applies to a radio or checkbox question, expose one group-level error rather than marking each option as an independent failure.
  • Do not rely on color alone. Pair the canonical invalid visual state with text and semantic state.
  • Use focus deliberately. Do not move focus for every inline error. When a failed transition would otherwise leave errors difficult to locate, move focus to an appropriate recovery entry point.
  • Summarize multiple failures when useful. Longer forms or submissions with several errors may provide a form-level error summary that identifies and links to affected controls; the summary complements rather than replaces inline messages. When that summary provides the clearest recovery entry point after a failed submission, move focus to it deliberately and keep each summary item associated with its corresponding field.
  • Avoid assertive noise. Do not make every inline validation update an urgent announcement. Use live or alert behavior only when the interaction genuinely requires immediate announcement.
