Input

A native text-entry control with configurable size, alignment, contextual content, native states, and an optional trailing action. Lit and React adapters restore the value supplied before their first render on native form reset; later value updates change the current value without replacing that reset default.

WCAG 2.2 AA target

Accessibility notes
  • The action retains keyboard focus after activation.
  • Its accessible name changes between Show password and Hide password.
  • Localize both action states with data-input-password-show-label and data-input-password-hide-label in HTML, or showPasswordLabel and hidePasswordLabel in Lit/React. English remains the default.
  • The decorative eye icon does not duplicate the button accessible name.

Component contract

Accessibility

WCAG 2.2 AA target

Native semantics

  • Uses a native input for text editing, keyboard behavior, validation, focus, and form participation.
  • Uses a separate composite wrapper only for presentation and optional adjacent content.
  • Derives visual disabled, readonly, invalid, and focus states from the native input.
  • The native input remains the text-entry and form control when an optional trailing action is composed.
  • Password visibility uses a native button whose accessible name changes with the revealed state.
  • Form Label, supporting/help text, and validation-message markup are external field composition rather than Input anatomy.

Requirements

  • Every input must have an accessible name supplied by a visible label, aria-labelledby, or aria-label.
  • Visible labels are preferred over placeholder-only identification.
  • Placeholder content must not be the only accessible label.
  • Validation errors and formatting instructions should be connected with aria-describedby.
  • Set aria-invalid when an entered value is known to be invalid.
  • Use the native disabled attribute to disable the field rather than a styling-only data attribute.
  • Use readonly when users should be able to focus, select, and copy a value without editing it.
  • Decorative glyphs and icons must use aria-hidden="true".
  • Any important prefix, suffix, unit, or icon meaning must also appear in the accessible label or description.
  • Do not add tabindex="0" to the wrapper because the native input is already keyboard focusable.
  • Do not replace the native input with a div, contenteditable region, or scripted textbox role.
  • Use a native button with an accessible name for an interactive trailing action.
  • For password visibility, change the action accessible name between Show password and Hide password without duplicating state with aria-pressed.
  • Disable the password visibility action whenever its associated native input is disabled.

Keyboard

Tab
Moves focus to the enabled native input according to document order.
ArrowLeft / ArrowRight / Home / End
Uses native browser text-navigation behavior for supported input types.
Enter / Space
Uses native button activation to reveal or hide password text.
