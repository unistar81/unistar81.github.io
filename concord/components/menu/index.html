Menu

An action-oriented composite menu built on the native Popover API. Menu owns command semantics, arrow-key focus movement, and optional leading/content/trailing item regions without becoming a navigation or form-selection replacement.

WCAG 2.2 AA target

Example 01

—

Actions and shortcuts

A native Button opens a start-aligned Menu. Optional leading icons and trailing shortcuts compose inside the same item anatomy while unused regions are never rendered.

 * popovertarget supplies the implicit anchor relationship. Menu defaults to
 * bottom/start; side and alignment remain independent configuration axes.

  --dsl-icon-size: 0.875rem;

@supports (position-area: block-end span-inline-end) {
  .dsl-menu[popover] {
    inset: auto;
    margin: 0;
    block-size: max-content;
    max-block-size: min(
      var(--_dsl-menu-max-block-size),
      calc(100% - var(--_dsl-menu-anchor-gap) - var(--_dsl-menu-viewport-gap))
    );
    justify-self: auto;
    align-self: auto;
  }

  /*
   * Use position-area for all placement. The Popover API supplies the implicit
   * anchor relationship through popovertarget, so Menu does not need explicit
   * anchor-name/position-anchor plumbing or anchor() inset calculations.
   *
   * The spanning area makes exact start/end edge alignment possible:
   * bottom/start begins at the trigger's inline-start edge, while bottom/end
   * ends at the trigger's inline-end edge.
   */
  .dsl-menu[popover]:is(:not([data-side]), [data-side='bottom']) {
    margin-block-start: var(--_dsl-menu-anchor-gap);
    position-try-fallbacks: flip-block;
  }

  .dsl-menu[popover]:is(:not([data-side]), [data-side='bottom']):is(
      :not([data-align]),
      [data-align='start']
    ) {
    position-area: block-end span-inline-end;
    justify-self: start;
  }

  .dsl-menu[popover]:is(:not([data-side]), [data-side='bottom'])[data-align='center'] {
    position-area: block-end center;
    justify-self: anchor-center;
  }

  .dsl-menu[popover]:is(:not([data-side]), [data-side='bottom'])[data-align='end'] {
    position-area: block-end span-inline-start;
    justify-self: end;

Component contract

Accessibility

WCAG 2.2 AA target

Native semantics

  • Uses a native button trigger with aria-haspopup="menu" and popovertarget.
  • Uses role="menu" on the native Popover surface and native button elements with role="menuitem" for actions.
  • Treats Menu as a composite widget: items use tabindex="-1" and behavior moves DOM focus with arrow keys.
  • Uses aria-disabled rather than native disabled so unavailable menu items remain focusable during arrow navigation.

Requirements

  • Use Menu for actions/commands, not ordinary site navigation or form selection.
  • Every Menu Item needs a meaningful visible label.
  • Decorative leading icons and visual shortcut text must not duplicate accessible output.
  • Do not nest independent interactive controls inside a Menu Item.
  • Preserve native Popover light dismiss and top-layer behavior.

Keyboard

ArrowDown
From the trigger opens the Menu and focuses the first item; inside the Menu moves to the next item.
ArrowUp
From the trigger opens the Menu and focuses the last item; inside the Menu moves to the previous item.
Home / End
Moves to the first or last Menu Item.
Enter / Space
Activates the focused item unless aria-disabled is true.
Escape
Closes the Menu and returns focus to its trigger.
Tab / Shift+Tab
Leaves and closes the Menu without trapping focus.
Printable characters
Moves focus to the next item whose label begins with the typed prefix.
