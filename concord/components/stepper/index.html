    inline-size: var(--dsl-component-stepper-control-size);
    block-size: var(--dsl-component-stepper-control-size);
    padding: 0;

    /*
     * Stepper is a composite control. Match the +/- control stroke to the
     * nested Input stroke so the three-part control reads as one system.
     * This remains theme-aware because component.input.border.width is a
     * generated component token that themes may override.
     */
    border-width: var(--dsl-component-input-border-width);

    /*
     * CONCORD STEPPER COMPOSITION CONTRACT
     * Stepper composes canonical secondary Button controls.
     * Button owns foreground, background, border color, and interaction-state
     * colors so each theme keeps a single tested contrast pair.
     * Stepper owns only composite geometry and the Input-matching border width.
     */
  }

  > .value > .dsl-input {
    --dsl-input-width: 100%;
  }

  > .value input[type='number'] {
    appearance: textfield;
    text-align: center;
  }

  > .value input[type='number']::-webkit-inner-spin-button,
  > .value input[type='number']::-webkit-outer-spin-button {
    appearance: none;
    margin: 0;
  }
}

Component contract

Accessibility

WCAG 2.2 AA target

Native semantics

  • Uses a native number input for direct editing and native buttons for explicit decrement and increment actions.
  • Form Label, supporting/help text, and validation-message markup are external field composition rather than Stepper anatomy.

Requirements

  • Provide the native numeric input with an accessible name using a visible external label, aria-labelledby, or aria-label.
  • Give decrement and increment buttons accessible names that communicate both the action and increment amount.
  • Keep each action associated with the numeric input through aria-controls.
  • When external supporting or validation content applies, associate it with the numeric input using aria-describedby.
