Card

A single Card anatomy composes the Media presentation primitive, uses declarative data attributes to select media, article, collection, promo, poster, and app presentations, and adapts each configured Card through container queries.

WCAG 2.2 AA target

Demo media

Choose how Card media is rendered

Wireframes are selected by default so anatomy, configuration, and responsive behavior remain easy to compare. Switch source geometry to verify that Card's nested Media frame normalizes both matching and mismatched inputs into each required presentation.

Paste a direct image URL to test arbitrary source geometry across every Card presentation without changing the authored examples.

Direct HTTP or HTTPS image URLs work best. Some hosts may block external embedding.

Selected preview media: Wireframe

One anatomy, declarative configuration

Card expression is selected through data attributes, the nested Media frame owns source cropping and presentation geometry, and container queries adapt each configured Card to the space provided by its container.

data-variant data-layout data-collection-type data-media-shape

Source controls change live previews only; implementation drawers keep the authored wireframe source. A 1:1 portrait therefore crops into 16:9 Article and Media frames, remains 1:1 in Collection and square Poster frames, and adapts to 2:3 Poster frames. Custom URLs follow the same Media presentation contract. The App example keeps its dedicated artwork.

Component contract

Accessibility

WCAG 2.2 AA target

Native semantics

  • The custom Card host is a presentation/composition boundary; native links and media descendants retain their own semantics.
  • Uses native links for wholly clickable cards and independent native links for cards with multiple actions.
  • Keeps media alternative text independent from visible Card headings.
  • Keeps concise visual labels inside the Card media wrapper without changing link semantics.

Requirements

  • Do not wrap multiple interactive descendants in a single Card link.
  • Use alt="" when the Card image duplicates information already conveyed by the linked heading.
  • Use meaningful alternative text when the image contributes information not present in adjacent text.
  • Keep the visible Card heading descriptive enough to name its destination.
  • Do not use Card hover elevation as the only indication that content is interactive.
