Tabs

A keyboard-operable tab set with dropdown, stacked, or accordion presentation at narrow widths.

WCAG 2.2 AA target

Example 01

—

Default tabs

Establishes the canonical horizontal tab pattern with substantive account content before introducing responsive presentation changes.
Preview width
Auto

Your workspace brings together account information, recent activity, notification preferences, and security settings. Changes made here apply across every project associated with this account. Use this overview to confirm account ownership, workspace access, and the most important settings before moving into more detailed areas.

Recent account activity is retained for 90 days. Review sign-ins, profile changes, connected applications, and administrative actions from one place. Entries are presented chronologically so unusual access or configuration changes can be identified without leaving the account view.

Control notification, privacy, and security preferences for this account. Organization-level policies may override individual settings when required. Settings that are managed by an administrator remain visible so the account-level behavior is understandable even when a preference cannot be changed locally.

Example 05

—

Keyboard navigation

Arrow keys move focus and activate tabs automatically; Home and End move directly to the first and last tab.
Preview width
Auto

Use Right Arrow to move forward. Focus movement also activates the destination tab because Concord uses automatic activation.

Use Left Arrow to move backward. Home and End provide direct movement to the first and last tabs in the set.

Use Home and End to move to an edge. The selected state, roving tabindex, and visible panel remain synchronized.

Component contract

Accessibility

WCAG 2.2 AA target

Native semantics

  • Uses a labelled tablist containing native buttons with role=tab.
  • Uses one selected tab and one visible tabpanel at larger widths.
  • Uses a native select for the dropdown presentation.
  • Uses native disclosure buttons and labelled regions for the accordion presentation.

Requirements

  • Every tab must reference a unique panel ID through aria-controls.
  • Only the selected tab may use aria-selected=true and tabindex=0.
  • Selection must remain synchronized across viewport presentation changes.
  • Hidden responsive interfaces must use the hidden attribute.
  • Do not use Tabs for sequential steps or unrelated page navigation.

Keyboard

ArrowRight / ArrowLeft
Moves and activates selection in a horizontal tablist.
ArrowDown / ArrowUp
Moves and activates selection in the stacked vertical tablist.
Home / End
Moves to and activates the first or last tab.
Enter / Space
Uses native activation for accordion triggers and tab buttons.
