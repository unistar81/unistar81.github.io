Template state note

The criteria remain while the collection slot changes

The application chooses the current state; Concord Patterns determine how waiting, known-zero, and failure are communicated.

Loading Loading & Progress replaces results while the outcome is unknown.
Known zero Empty States replaces results and Pagination while criteria remain available.
Failure Status and recovery replace results without erasing query context.

04 / Recorded limitations

Where the result stops

  • The existing template is a document-collection specimen with fixed example data. Customer labels, filter values, metadata, counts, and destinations require application-specific content.
  • Search execution, filtering logic, data fetching, routing, and state management are outside Concord’s ownership under AGENTS.md. The specimen does not establish a working customer backend.
  • Loading, zero-result, and failure handling are described as application-selected states, not implemented customer workflows.
  • No files were modified and no builds or tests were run.
Read the recorded observations and selections
  • The template explicitly selects canonical component sources through named dependencies; it does not introduce a customer-record component.
  • Record markup uses native list items and anchors. Supporting text and metadata belong within the existing content hierarchy.
  • The pagination specimen preserves query and filter parameters in links, marks the current page with aria-current="page", and renders unavailable Next as non-interactive text.
  • apps/docs/tests/template-list-index-page.e2e.test.ts contains checks for composition, accessible search, pagination context, semantic order, and narrow-width containment.
