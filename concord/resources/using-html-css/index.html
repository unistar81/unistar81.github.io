Using HTML & CSS

HTML and CSS are first-class Concord delivery targets. Consumers can use semantic component markup, generated token custom properties, authored CSS, and framework-agnostic enhancement without adopting a JavaScript component framework.

Platform-native path

The web platform is a delivery target, not a fallback

The HTML/CSS path is the canonical proof that Concord’s design language is not owned by a framework. Design decisions, semantics, visual contracts, accessibility, and component-owned behavior remain available through the web platform.

Canonical static distribution

No application framework is required to consume the shared language.

  1. 01 Design decisions Tokens and shared contracts
  2. 02 Semantic HTML Native structure and browser behavior
  3. 03 External CSS Authored presentation and custom properties
  4. 04 Enhancement JavaScript only where required

Load the layers

Consume the system in dependency order

Concord separates design decisions, shared foundations, component presentation, semantic markup, and optional behavior so consumers can understand what each layer owns.

  1. 01 Design decisions Generated token CSS

    exposes shared design decisions as CSS custom properties.

  2. 02 Shared foundations Core CSS

    provides system-level foundations shared across components.

  3. 03 Component presentation Component CSS

    provides authored presentation for individual component contracts.

  4. 04 Document semantics Semantic markup

    uses the canonical static host and DOM for the component.

  5. 05 Optional behavior Behavior where required

    adds framework-agnostic enhancement only when native HTML does not already provide the required behavior.

Distribution paths are evidence-bound.

Distribution file paths remain repository-owned. Do not document a generated path or package entry point unless the current distribution or package export map proves it exists.

Load base token CSS, then the selected Theme, Density, and Appearance files, followed by core and component styles. Consumer token overrides come last. Core CSS declares the Concord layer order and includes document-wide foundations such as box sizing, body defaults, and form-font inheritance; it is not an isolated widget reset.

Light DOM deliberately participates in the host cascade. Put a host reset in an earlier named layer and predeclare the intended order before loading styles. The aggregate components.css places component rules in dsl.components; a direct selective component stylesheet is unlayered unless the consumer imports it with layer(dsl.components). Use a CSS entry such as @import url('@dsl/css/components/button.css') layer(dsl.components) when matching the aggregate layer behavior. Unlayered host rules can override layered Concord rules regardless of file order. Scope application selectors and prefer public token/custom-property overrides; naming prefixes do not provide style isolation.

Host selection

Choose the host by semantic responsibility

Choose the component host from the component’s semantic and architectural role rather than from naming consistency.

Use a native HTML element when the platform already represents the component’s semantics or browser behavior. Use an autonomous `<dsl-*>` host when the component is a meaningful design-system composition or presentation abstraction and no appropriate native host represents that boundary.

Do not introduce a custom-element host merely for naming consistency, styling hooks, Lit convenience, React integration, or DOM uniformity. Custom elements extend the platform; they do not replace native semantics.

01 Native primitive exists
Keep the native element as the canonical host.
02 No appropriate native primitive
Use a custom host only for a meaningful Concord-owned boundary.

Do not normalize the DOM for consistency alone. Do not add a custom host only to normalize naming, styling hooks, framework integration, or DOM shape.

Canonical markup

Do not simplify the DOM contract for documentation convenience.

Use canonical snippets from `packages/html` or the current successor package. Do not hand-author a simplified example that disagrees with the canonical component DOM.

Semantic authority

Adapters do not replace native semantics

Divider and Progress Indicator deliberately keep native canonical hosts even when Lit or React expose adapter APIs. Breadcrumb and Pagination follow the same principle: adapters can improve consumption ergonomics while the rendered semantic structure continues to own navigation, list, current-page, and link behavior.

Progress Indicator remains determinate. Loading Indicator owns unknown-duration loading.

Canonical HTML/CSS contracts remain authoritative across delivery interfaces. Lit Web Components and framework adapters can expose ergonomic APIs, but they must preserve the same semantic, token, CSS, accessibility, and behavior contracts rather than redefine them.

Behavior boundary

Enhance only when the platform stops

Where a component needs behavior beyond native HTML, use the framework-agnostic enhancement supplied by the static distribution.

Do not imply every component requires JavaScript. Native HTML remains authoritative wherever the platform already provides the required behavior.

For mounted regions, pass an optional lifetime signal: enhanceTabs(container, { signal: lifetime.signal }), where lifetime is an AbortController. Abort before removing or replacing the region; use a new controller to remount. The same option works on every selective enhancer and enhanceDesignSystem. Existing return values are unchanged. The first enhancement owns the node, so a later scan does not acquire or dispose another caller's listeners. Without a signal, enhancement lasts for the document lifetime. Do not enhance Lit/React-managed internals independently.

Canonical HTML owns localized text and accessible names. The password action accepts data-input-password-show-label and data-input-password-hide-label; provide both translated states. Enhancement preserves the authored reveal label when no explicit show label is supplied. Changing lang alone does not translate strings.

Native first Browser behavior remains authoritative.

Do not add JavaScript when semantic HTML already supplies the required behavior.

Enhance when required Component-owned behavior stays framework-agnostic.

Use the static distribution’s enhancement layer when behavior exceeds native HTML.

Architecture proof

The HTML/CSS path proves that Concord’s shared language can survive framework changes. Frameworks are delivery interfaces around the system, not prerequisites for its semantics, styling, accessibility, or design decisions.
